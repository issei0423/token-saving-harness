# 予算（詳細）

`graph.md` から切り出した（読む合図：「→ 読む：budget.md」）

## 見方

- **`bash ~/.claude/token-harness/core/budget.sh 85 50`** で見る。引数は `<5時間枠の線> <7日枠の線の下限> [fixed] [--json]`。中身は `core/budget.py`（`budget.sh` は包み）
- 元データは `~/.claude/statusline-last.json`（`statusline/statusline-tee.sh` が、ステータスラインに渡る JSON を保存したもの）の `rate_limits`
- 出る行は順に：いまの時刻／5時間枠／7日枠／7日枠の線／ペース／**判断：**／「注意：」の行（あるときだけ）／最後の行 `GO` か `STOP`（読めないときは `UNKNOWN`）
- **読めないときは、1行目が時刻にならない**（「statusline-last.json が無い。予算を読めない」などのわけ、次に「判断：読めない」、最後に `UNKNOWN`）。そのときの時刻は `date` などで取り、予算を読めなかったと状態ファイルに書く
- 終了コード：`GO`＝0、`STOP`＝1、読めない＝2
- 新しい実行の点を出す前に見る。**5時間枠が 85% を越えたら新しい点を出さず**、動いている係を区切りまで終わらせ、状態ファイルを書いて報告する（85% は作者が置いた既定）
- 持ち主が別の線（「90% まで」など）を言ったら、そちらに従う

出力の例：

```
いま 11-07 09:36 +0900（statusline-last.json は 0 分前のもの）
5時間枠：18%（線 85% をまだ）／11-07 13:20 に戻る（あと 3時間43分）
7日枠：58%（線 85% をまだ）／11-07 23:00 に戻る（あと 13時間23分）
7日枠の線：85%（経過 92.0%＝1−残り分/10080。…）
ペース：0.63（使用率 58% ÷ 経過 92.0%。1.3 を超えると小さく）
判断：契約の枠（線の手前。契約の枠で出す）
GO
```

## 7日枠の線とペース（式）

- 経過 ＝ 1 − 残り分 / 10080（10080 分＝7日。窓は戻る時刻の7日前に始まる前提で、**推測**。経過の割合を出力に出すので、数日分を見比べて確かめる）
- 線 ＝ (100 − 残す分) × 経過 ＋ 余裕 を、上限 100 − 残す分 で切り、**第2引数（下限）より下げない**
- 残す分 15・余裕 15 なので、上限は 85%。週の初めは下限の 50%、週が進むほど上がる
- ペース ＝ 使用率 ÷ 経過。1.3 を超えたら「小さく」
- 固定の線だと、週の終わりに枠が余っていても止まる（作者の例：残り14時間で 44% 残っていても、固定の 50% で止まっていた）。だから残り日数で動かす

## 3つの判断（「判断：」の行）

| 判断 | 最後の行 | いつ | 頭役がすること |
| :-- | :-- | :-- | :-- |
| 契約の枠 | GO | 5時間枠も7日枠も線の手前で、ペースが 1.3 以下 | 係を出す（同時4体まで） |
| 小さく | GO | 線の手前だが、ペースが 1.3 を超えた | 同時2体まで。research・test の点を先に |
| 待つ | STOP | 5時間枠か7日枠が線を越えた | 新しい点を出さない。戻る時刻を報告に書く |

## 値の正（core/budget-policy.json）

値はどれも作者が置いた既定。自分で決めたら書き換える。読めない欄は `budget.py` の既定（同じ値）を使う。

| 欄 | 値 | 意味 |
| :-- | :-- | :-- |
| `reserve_pct` | 15 | 週の終わりに自分の作業に残す %（線の上限は 100 − これ） |
| `slack_pct` | 15 | 線に足す余裕 % |
| `pace_small` | 1.3 | ペースがこれを超えると「小さく」 |

## 読めないとき

- `statusline-last.json` が書かれている途中で壊れて見えるときは、0.3秒おいて3回まで読み直す。それでもだめなら頭の1つの JSON だけを読み、「注意：」の行を出す
- ファイルが無い・読めない・`rate_limits` に枠が1つも無いときは「判断：読めない」、最後の行 `UNKNOWN`、終了コード 2
- `rate_limits` は、契約プラン（Pro・Max など）でログインした Claude Code のステータスラインに出る。API キーで使っているとき、版が古いときは出ない
- `statusline-last.json` はステータスラインが描かれたときにしか書き換わらない。`budget.sh` が「15分より古い」と言ったら、古いまま判断したと報告に書く
- 枠が戻る前後は、片方の枠が無いことがある。そのときは「読めない」と出して、ある方だけで判断する

## 固定の線で見る（fixed）

- `bash ~/.claude/token-harness/core/budget.sh 85 50 fixed` で、7日枠の線を第2引数そのもの（50%）にして見る。持ち主が「50% で止めて」と言ったときや、動く線を疑うとき
- JSON で見るときは `bash ~/.claude/token-harness/core/budget.sh 85 50 --json`（終了コードは同じ）

## 見積もりと見張り

- 動いている係の分は、終わるまで使用率に乗り続ける。線の手前 10% で新しい点を止め、出すなら小さい点にする（作者の実測：6体同時で、24分で41%増えた）
- **見積もりの目安**（作者の実測）：4体を同時に動かすと、5時間枠は1分におよそ 0.7〜0.9% 減る。見直しの係1体は約30分で 25〜60万トークン、実行の係は30〜55分。線に届く時刻を `budget.sh` の値で見積もり、終わる時刻より先に届きそうなら、新しい係を出さずに動いている係へ続けて頼む
- 線の手前で待つときは、`budget.sh` の終了コードで見張る：`while :; do bash ~/.claude/token-harness/core/budget.sh <線> 50 >/dev/null; [ $? -ne 0 ] && break; sleep 60; done` を Bash の `run_in_background` で回し、届いたら動いている係へ「区切って」と送る。JSON を直に読まない（枠が戻る前後は欄が無いことがある）
- `[ $? -ne 0 ]` にするのは、`[ $? -eq 1 ]` だと読めない（終了コード 2）ときに永久に回るため。2 で抜けたときは「予算を読めなかった」と報告する
