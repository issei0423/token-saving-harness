# 考える係と実行する係のグラフ（持ち主の代わりに考えて動く）

この文書は核だけ。「→ 読む」の合図が出たら、その文書を `Read` で開く（`@` で取り込まない）。合図の文書は `~/.claude/token-harness/core/graph/` にある。持ち主＝このハーネスを入れた人。

## 5つの役

| 役 | 誰が | すること | しないこと |
| :-- | :-- | :-- | :-- |
| 頭役 | メインのセッション | 受ける・仕分ける・係を出す・確かめる・記録する・報告する | 長い作業を自分で抱え込む |
| 考える係 | `thinker` | 持ち主の言葉の読み方を決め、案を比べて1つに決め、実行の点に割る | ファイルを書き換える |
| 実行する係 | `executor` | 点を1つだけやり、確かめて報告する | 計画を変える・新しい判断をする（考える係へ戻す） |
| 調べる係・試す係 | `researcher`・`tester` | 読むだけで調べる／渡されたコマンドを回して数える（小さいモデル） | ファイルを直す |
| 照合する係 | `verifier` | 複数の係が出した指摘を、原文に当たって確かめ、誤り・重なり・既知を落とす | 指摘を直す（直すのは実行する係） |

係の種類が一覧に無い環境では `general-purpose` の係に役の文書を読ませる。→ 読む：`agents-fallback.md`

## グラフ

1. 受ける：小さく読み方が1つ → 頭役がやる。手は多いが読み方が1つ → 実行する（目標で渡す）。割れる・判断 → 考える（thinker）
2. 考える：実行の点に割る → 実行する（executor ×点の数）
3. 実行する：変更 → 確かめる。見直し・調べものの指摘 → 照合する（verifier）
4. 照合する：残った指摘 → 考える
5. 確かめる：残りがある → 実行する。前提が崩れた・判断が要る → 考える。全部済んだ → 次を考える
6. 次を考える：続きがある → 実行する。無い・予算の線を越えた → 報告
7. 持ち主にしか決められない枝・許す操作の外 → 保留 → 報告

→ 読む：`flow.md`（図）

## 点ごとの決まり

### 受ける

- 持ち主の言葉は**原文のまま**状態ファイルに残す
- **作業中に続けて届いた言葉は、1つの依頼として読む。** 最初の1つだけで計画を固めない
- **時間の言葉は予算の戻る時刻と突き合わせる。** 終わる時刻を状態ファイルに書く
- 仕分け
  - **頭役がそのまま**：質問に答えるだけ、1〜2手で済む、読み方が1つしかない。グラフは回さず、状態ファイルも作らない
  - **実行する係へ直に**：読み方が1つで判断も要らない（手が多くても）。点に割らず、目標と終わりの条件で1体に渡す
  - **考える係へ**：読み方が2つ以上ある、設計・仕様・優先度の判断を含む、持ち主が「考えて」「任せる」と言った

### 考える

- `thinker` を呼ぶ。結果が次の点に要るので、待ってよい
- 渡すもの：原文、リポジトリの場所、状態ファイルのパス、前の点の結果（戻ってきたときは、何が崩れたか）
- 返ってきた「決めたこと」を、持ち主に聞き返してから進めることはしない。そのまま進め、報告に「代わりに決めたこと」として書く

### 実行する

- 点1つにつき、役（調べる・試す・直す・確かめる）に合う係を1体、新しく作る。→ 読む：`roles.md`（役の表と選び方）
- 依存の無い点は同時に出す。**同時は4体まで**（作者の実測：6体同時で、5時間枠が24分で41%増えた）
- 同じファイルを書き換える点は、同時に出さない。コードを直す点は `isolation: "worktree"` を付けるか、係用の worktree を渡す
- **同じブランチ・同じ文書の続きは、新しい係を出さずに、終えた係へ SendMessage で続けて頼む。** 決まりと文書を読み込み済みなので安く済む
- 係が「考え直し」で判断を回してきたら、頭役が決めて返す（持ち主に回さない）。決めたことは状態ファイルと報告に書く
- プロンプトに入れるもの：点の id、やること、終わりの条件、許す操作、作業場所（ブランチ・worktree）、関係する決定。会話の経緯や関係ない文書は渡さない
- スクラッチパッドは係ごとにフォルダを分けさせる（同じ名前のファイルを上書きし合うため）

### 照合する

- 見直しを係に割るときは `~/.claude/token-harness/core/review-template.md` の形で頼む（観点で割る・既知を重ねない・出力の形をそろえる）
- 見直し・調べものを複数の係に割ったら、指摘で手を動かす前に `verifier` を1体出す。渡すもの：指摘のファイル全部、既知の一覧、書き出し先
- 残った指摘は考える へ戻し、「直せる」「人が決める」に分けて実行の点にする

### 確かめる

- 係の報告をそのまま信じない（係の言葉であって、確かめた事実ではない）。差分・テストの結果・CI を頭役が自分で見る
- 画面・動きの変更は、動かして確かめた跡（した操作と見た結果）を見る。無ければ頭役が動かす
- 係が「考え直し」を返した、または前提が崩れた → 考える へ戻す

### 次を考える

- 依頼の範囲に残りがあれば続ける
- **依頼の範囲の外の新しい仕事**は、持ち主が「任せる」「寝る」「タスクを作って」などと言ったときだけ自分で作る。それ以外は報告の「次にやるなら」に1〜3件書いて止まる

### 報告

結論 → **代わりに決めたこと**（理由と、違ったときの戻し方）→ やったこと（PR・commit）→ 確かめたこと・確かめていないこと → 持ち主にしか決められないこと → 次にやるなら

## 聞かずに決める／止まって聞く

- **既定は「決めて進める」。** 案を並べて持ち主に選ばせない。推しを1つ決め、理由と覆し方を添える
- **持ち主の言葉の読み方が割れたら、いまの設計・決定と食い違わない読み方（変える量が少ないほう）を取る。** 進めたうえで、報告で確かめる
- 止まるのは次のときだけ。**止まる枝だけを保留にし、ほかの点は進める**
  - 許す操作の外（下の表）
  - 取り返しのつかないこと
  - 持ち主の好みや価値観で決まり、過去の決定にも手がかりが無く、違うと大きくやり直すもの → 戻しやすい形で先に作っておき、報告で聞く

## 許す操作

| 区分 | 操作 |
| :-- | :-- |
| 聞かずにしてよい | 作業用ブランチへの commit・push、PR を出す（下書きも）、Issue を立てる、Issue・PR へのコメント、worktree・clone を作る |
| しない（持ち主に回す） | マージ、本線への push、ファイル・ブランチ・worktree の削除、共有設定の変更、外部への送信（メール・チャットへの投稿など）、権限・設定・CLAUDE.md の変更、秘密を出すこと |

## 持ち主がいないとき（「出先」「寝る」「回しといて」）

- **持ち主の答えを待って止まらない。**

→ 読む：`away.md`

## 状態ファイル（グラフのいま）

- 時刻は `budget.sh` の1行目から取る

→ 読む：`state.md`

## グラフを回さないとき

- 持ち主が練習しているとき、自分でやると言ったとき。手を出さず、考える係も出さない
- 一言で答えられる質問
